# wit-reflect adoption

Recorded on 2026-11-21. The component boundary is generated from the ordinary
Rust types and operations by
[wit-reflect](https://github.com/project-millipede/wit-reflect). This record
states what is generated, what is still written by hand, and the evidence. The
[generator comparison](rust-to-wit-generators/README.md) explains why the
library was written.

## What is generated

`pnpm contract:generate` writes three files into `crates/workbench/component`.
They are committed and never edited. `pnpm contract:check` changes nothing and
fails when one is stale; it runs in `pnpm test` and `pnpm wit:check`.

| File                | Lines | Content                                                                       |
| ------------------- | ----- | ----------------------------------------------------------------------------- |
| `wit/analysis.wit`  | 395   | The package: interfaces `binary`, `inspection`, `native` and world `analysis` |
| `src/bindings.rs`   | 31    | The contract's part of the `wit_bindgen::generate!` call                      |
| `src/forwarding.rs` | 46    | The implementation of the binding traits, calling the Rust operations         |

The conversion of each result is generated by the `WitType` derive inside the
crate that owns the type.

## What is written by hand

| Where                                         | Lines | Content                                                                   |
| --------------------------------------------- | ----- | ------------------------------------------------------------------------- |
| Owner crates, behind the `wit` feature        | 53    | 26 type derives, 1 resource derive, 6 `#[export]` marks, 20 rules         |
| `crates/binary/inspection/src/wit.rs`         | 81    | Contract representations of `object` values, which carry no derive        |
| `xtask/src/contract.rs`                       | 153   | Which interface exports what, the world, and the generate and check tasks |
| `crates/workbench/component/src/lib.rs`       | 50    | The bindings call, the session factory and the module list                |
| `crates/workbench/component/src/websocket.rs` | 73    | The transport over the imported Polymorph operations, unchanged           |

Every rule covers a field that has no WIT form as stored: `into` for `object`
values, `display` for versions and foreign errors, `widen` for `usize`, `skip`
for private cause fields, and a computed `message`. No name is set by hand. The
contract names derive from the Rust names, and the web application follows them.

## What it replaced

| Removed                                                             | Lines |
| ------------------------------------------------------------------- | ----- |
| Handwritten WIT: `world`, `inspection`, `native`, `deps/filesystem` | 232   |
| `native.rs`, `conversion.rs`, `inspection_error.rs`                 | 302   |
| The nine-entry `with` map in `lib.rs`                               | 9     |

The nine types of that map still cross unchanged. wit-reflect decides this per
type and generates the entries: `ContainerKind`, `MachOHeaderFormat`,
`AnalysisScope`, `StepKind`, `FailureKind`, `DirectoryEntryKind`,
`DirectoryEntry`, `SelectedResource` and `SelectionState`.

## Contract changes

The contract now has the shape of the Rust types.

| Before                                                            | Now                                                                                         |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `report`, `image`, `header-format`, `entry-kind`                  | `binary-report`, `mach-o-image`, `mach-o-header-format`, `directory-entry-kind`             |
| `choose-file`, `choose-folder`                                    | `select-file`, `select-directory`                                                           |
| `inspection-failure { message, details: list<inspection-error> }` | `inspection-failure { message, kind }` with the cases `selection`, `metadata`, `inspection` |
| One flat `inspection-error` variant                               | `analysis(analysis-error)` or `input(input-errors)`                                         |
| `read-error` of an owned `apple-code:filesystem` package          | `source-error` with the cases `cancelled`, `io(string)`, `provider(string)`                 |
| `source-operation`                                                | Removed; the stage is the case                                                              |

## Evidence

Permanent:

| Check                                                                       | What it establishes                                                                                      |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| The component compiles from the generated files                             | The contract, the bindings and the Rust types agree; a mismatch is a compile error                       |
| `contract check`                                                            | The committed files are what the declaration generates                                                   |
| `a_failed_inspection_keeps_its_message_stage_and_cause_across_the_boundary` | A failed read arrives with the Rust error's complete message, its stage, the read's offset and its cause |
| `a_selection_crosses_the_boundary_as_the_value_the_client_decoded`          | Selection data is the Rust value itself, and the bindings use the Rust types                             |

One-off, run by hand on 2026-11-21 against the production component under jco
1.42.0 on Node 24.15.0 with JSPI. A scripted WebSocket stood in for the native
service and passed each request to a Rust responder built from the fixtures of
the generator trials. The JavaScript side did not interpret the protocol.

| Scenario          | Result                                                                                                                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Success           | The complete report equals the frozen output of the handwritten adapter at commit `92ad854`                                                                                                 |
| Selection failure | Same message; `kind` is `selection` with a `failure`                                                                                                                                        |
| Metadata failure  | Same message; `kind` is `metadata` with a `failure`                                                                                                                                         |
| Unsupported image | Same message; `kind` is `inspection`, `analysis`, `unsupported-image`                                                                                                                       |
| Read failure      | `kind` is `inspection`, `input` with one `source` error at offset 0. The message names the WebSocket error the scripted socket raised, where the frozen output named an in-memory I/O error |

Field-rename trial: `BinaryReport::byte_length` was renamed to
`input_byte_length` in its owning type, with its two initializers. The check
reported the WIT as stale. After regenerating, the WIT had `input-byte-length`,
the TypeScript declaration had `inputByteLength`, the typecheck named the two
view lines that still read `byteLength`, and jco returned the value 40192 under
the new name. No conversion code was edited, because none is handwritten. The
trial was reverted.

Size of the packaged component: 299,338 bytes, against 296,069 bytes for a build
of the handwritten adapter from 2026-11-11. That is 1.1% larger. The two builds
also differ in wit-bindgen version and contract shape, so the figure is not a
measurement of the conversion alone.

## Limits and what is not verified

- The browser path with the native service and its dialogs was not run. The
  engine build, the typecheck and the tests cover it only up to the transport.
- One read failure was exercised. Several acquisition failures in one
  inspection, and their order, are not covered at the boundary.
- A successful report is covered by the jco run, not by a retained test.
- Parameters are limited to plain values. `open-file` and `open-directory` are
  ordinary Rust methods for that reason.
- jco 1.40.0 declares a struct-like case's record and the case itself under one
  TypeScript name. jco 1.42.0 does not; the workbench requires it.
- The session factory's signature is stated by hand in `xtask/src/contract.rs`,
  because the factory is implemented in the component crate. The generated
  forwarding calls the real function, so a wrong signature does not compile.
