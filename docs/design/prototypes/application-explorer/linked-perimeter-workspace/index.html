    Why a movable perimeter?

    This copy keeps the linked tree bridge workspace layout: physical tree, four-bridge canvas and a vertical inspector outside the graph. It replaces the fixed Atlas.app scope with a perimeter you can move, as explored in perimeter bridges.

    Bridges

    Bridge Direction Meaning
    North Other side → selection Ingress across the perimeter, through the north gate.
    West Same side → selection Internal ingress from inside the perimeter.
    East Selection → same side Internal resolution: targets that resolve, or are proposed to resolve, without leaving the perimeter.
    South Selection → other side Egress across the perimeter: system names, external paths, capabilities and files outside a narrow perimeter.
    Unplaced Either Containment unknown. Such endpoints are not treated as leaving the perimeter.

    Perimeter

    Atlas.app matches the linked tree workspace: everything in the application inventory is internal. Nearest bundle shrinks the frame to the closest enclosing bundle, or the selection itself when it is a bundle. The same record can then move, for example from West to North when Render Helper's dependency on Example.framework crosses the framework's edge. Switching never adds, removes or upgrades evidence; the tree marks the perimeter with a dashed rail.

    Tree follows connections

    With linking on, each related row receives a badge naming its bridge (N, W, E or S), ancestors open automatically and previewing a connection outlines its other endpoint. A file outside a narrow perimeter is still a file, so North and South rows can be marked too. Turn linking off to keep the tree to containment only; Reveal still locates an endpoint on request.

    Notes that follow a second hop

    • Bypass: an absolute load reference leaves the perimeter although a staged copy exists inside it. Copying or re-signing does not rewrite recorded paths.
    • Stand-in: the same pair seen from the staged copy, which is only a proposed candidate.
    • Round trip / provider: a service name leaves through the OS and a bundle inside matches it. Name matching does not establish registration or IPC.

    Try

    Select Example and switch the perimeter between Atlas.app and Example.framework. Then select Atlas on arm64 to see the bypass, and on x86_64 to see the bundle-relative reference resolve east. Select Render Helper with the nearest-bundle perimeter: Example.framework leaves south while RenderKit stays east.

    Evidence and implementation limits

    All data is authored for this design study. A recorded load name is not a loaded library; a candidate is not a resolved target; a seal entry or bound hash is not integrity or trust; an entitlement or path string is not observed access. Empty north bridges mean no records were supplied, not that no external consumers exist.

    This file uses only HTML, CSS and presentation JavaScript. Perimeter placement and the two-hop notes are computed here for discussion only; in a product they would be relationship semantics composed by their ordinary Rust owners under crates/binary/inspection. No resolver, filesystem acquisition, React, Wasm or service integration is added.
